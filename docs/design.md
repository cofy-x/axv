# AXV visual and interaction design

Use this guide for UI changes. It owns enduring presentation, interaction and accessibility rules. [Product direction](product.md) owns identity and goals; [desktop architecture](desktop.md) owns implementation; [usage](usage.md) owns action workflows.

## Brand and product voice

Use **AXV** for the visible product name and `axv` for technical identifiers. The tagline and name interpretation belong in [product identity](product.md#identity). Welcome, About and page metadata describe the enduring product purpose, without release notes, validation matrices or roadmap lists. Keep their claims consistent with [project status](../README.md#project-status), which owns those changing details.

Use direct action labels, identify the execution target and explain capability limits where they affect a choice. Product branding belongs in the dashboard and public assets; generic desktop controls remain reusable.

Keep buttons brief, usually one or two words. Use surrounding context instead of repeating object names. Put consequences in nearby guidance or confirmations, preserving execution targets and lifecycle distinctions.

Show guidance when it explains a restriction, progress or recovery. Omit routine instructions already clear from the visible controls.

Keep frequent actions visible and group secondary commands in one accessible menu. Name action menus for their view or selected target, including a short identifier when names can repeat. Use the shared icon button for familiar actions such as copy, paste and paging; keep lifecycle and destructive actions clearly named. Icon buttons retain accessible names, tooltips, focus feedback and touch hit areas.

Use short action labels without trailing ellipses, including commands that open a picker, panel or confirmation. Reserve ellipses for loading or in-progress text and actual truncation. The standalone More icon remains a menu affordance.

## Design sources and goals

[Window Maker](https://github.com/window-maker/wmaker/tree/535288cec55e99371f0996da9a12c1744a8a0f62) informs window chrome, Dock, Clip and menus. [GWorkspace](https://github.com/gnustep/apps-gworkspace/tree/6c49cd9071ffca4dd385bb3184a0ceb087a9b09c) informs column navigation and Inspector; [GNUstep GUI](https://github.com/gnustep/libs-gui/tree/fdc5cfe833f23ae1fd50e9ba6ce389c50f97c30f) informs compact raised and recessed controls. These references pin the inspected revisions. AXV bundles no native code, artwork or fonts from them; external material follows [AGENTS.md](../AGENTS.md).

Preserve the compact workstation language: dark active titles, square gray controls, crisp bevels, substantial application tiles and overlapping windows. Dock, Clip, miniwindows, fixed menus and Inspector have distinct roles. Readability, Unicode, keyboard access, touch and modern display scales take priority when adapting a historical detail.

## Visual rules

- **Surfaces:** Use gray hierarchy, square corners, thin dark outlines and small hard shadows. Raised surfaces have light upper/left edges and dark lower/right edges; editable areas are recessed. Use the shared neutral and bevel tokens rather than inventing equivalents.
- **Color:** Preserve dark selection and a distinct focus outline. Active titles are nearly black with white text; inactive application titles are gray, while utility panels keep their darker treatment. Use stronger color for meaning and pair status color with text or another cue. Wallpaper must leave windows and labels legible.
- **Typography:** Use the shared sans-serif UI stack and monospace where alignment matters. Keep compact bold titles and readable body text, including fallback glyphs for non-Latin content. Do not shrink text to hide overflow.
- **Icons:** Reuse the SVG system and application-tile proportions. Match silhouettes, detail and apparent size across launchers, miniwindows, menus and toolbars. Distinguish applications from their content: text files use a plain document, Text Editor adds a pencil, and Project Files adds a code panel to its folder. Application Manager uses an application drawer and cards; Checklist uses a warm paper clipboard with green checkmarks. Both are original shared drawings, and Checklist's example header uses the same artwork. Cloudflare uses an original generic cloud and tunnel drawing, with readiness shown by the panel's labeled status. Sample documents use normal file icons independent of their names. Add labels where icons are ambiguous; check thin edges at integer and fractional display scales.
- **Spacing:** Keep related toolbar actions compact and aligned. Group navigation separately from item actions, keep primary actions near the target identity, and allow groups to wrap in narrow windows. Truncate long titles, wrap explanations and place lengthy errors with their recovery actions in a scrollable or wrapping content area.

## Window and control presentation

Applications use the shared title bar, optional toolbar, scrolling content and optional status bar. Keep the resize strip visible on resizable desktop windows. Minimize belongs on the left and close on the right; folding and maximizing remain separate.

| State | Presentation |
| --- | --- |
| Available | Clear label with the shared raised or inset treatment |
| Pressed | Visible surface or bevel change while engaged |
| Selected or checked | Persistent highlight or mark |
| Keyboard focus | Visible outline distinguishable from selection |
| Default dialog action | Shared stronger border and label, without hiding focus |
| Disabled | Muted but legible control and label |
| Error or unavailable | Nearby explanation and useful recovery action |

Empty, loading, failed and unsaved states are part of the design. Preserve visible work during recovery and report success only after the action succeeds.

Load application content inside its existing window, with a concise accessible status and a local Retry action on failure. Keep diagnostics expandable and long errors wrapping on narrow screens. Loading and retries must preserve other windows, drafts and sessions; they must not queue input, steal focus or automatically reload the desktop. Keep unavailable owner commands disabled until the original view registers them.

Use shared Tabs for sections within a panel and ButtonGroup for related mode or filter buttons. Tabs join the selected section to its content surface; button groups use a shared pressed treatment. Keep each control's existing state and focus behavior, and retain panel contents when switching would otherwise discard work.

Keep browser/server connectivity and application remote-access readiness distinct. The Tailscale utility controls AXV’s embedded private entrypoint and does not display system VPN state. The separate Cloudflare utility distinguishes missing setup, disabled access and a listening local origin. Its amber “Listening locally” state must not imply public tunnel readiness, and a configured origin address must not imply an active listener. Both utilities stop polling while inactive and keep privileged diagnostics local. Status lamps need text labels, and a failed status query must not retain a current-looking success lamp.

Cloudflare uses four compact shared tabs: **Overview**, **Setup**, **Publishing** and **Traffic**, with refresh actions inside the relevant view instead of a repeated application toolbar. Overview shows the public-access limitation once; detailed check scope and connection lifetime belong in Help. Setup uses a local configuration form and an account wizard with validation, explicit confirmation, revision-checked saving and password-only credential input. The wizard prioritizes its current step, keeps the account overview and credential rotation out of the active flow, and offers **Save settings** at its final step. Show configuration blockers beside the affected save action only when edits need saving. Keep advanced manual guidance and on-demand Diagnostics secondary; remote owners receive public Help and authorized publishing/traffic controls while configuration and raw diagnostics stay local.

Publishing reviews the captured project/VM, port, short name, allocation domain and access choice together, defaults to owner authentication, and shows the assigned hostname on the accepted record. Full request, host and boot identities belong in expandable Details during normal work; uncertain submissions keep their original request identity and recovery guidance visible. Every publication retry that can reopen access requires an explicit confirmation, with the original hostname, target, boot and access choice presented separately and **Cancel** as the default. Restarted publications label this action **Resume**. Retained or stale status must not bypass review; cleanup retries describe removal without promising to reopen access. Preserve drafts when another project requests this singleton window; choosing a new target requires a decision. Report accepted work separately from completion and keep failed cleanup retryable. Zone traffic identifies its scope and unavailable data rather than substituting zero, uses compact period labels and preserves full timestamps in semantic time elements. Pending desktop changes identify enabling or disabling. Preferences groups both utilities under **Remote access**, with separate named launch actions. Connection utilities remain non-modal, and optional Dock and Clip shortcuts follow their existing application roles.

## Interaction conventions

- **Windows:** Activation raises a window; title dragging moves it and edge dragging resizes it. Title double-click folds it. Folded, minimized and off-workspace content retains state without receiving input. Keep visible menu alternatives for these operations.
- **Available space:** Moving, resizing and maximizing use one window area. Reserve the miniwindow strip only while it contains current-workspace or sticky windows; keep Dock accessible. Temporary fitting preserves normal and restore geometry.
- **Desktop roles:** Dock represents applications and running state; miniwindows represent individual windows; Clip switches workspaces and holds shortcuts. Keep them visually distinct. Fixed menus retain their original owner even after another window activates.
- **Focus:** Modal dialogs contain focus only while open and return it on dismissal. Inspector and fixed menus remain non-modal. Inspector shows whether it follows selection or is pinned. Hidden terminals must not capture input or steal dialog focus.
- **Keyboard and touch:** Preserve editing shortcuts, clipboard, selection and composition. Menus support arrows, Enter and Escape; narrow submenus use a single panel with Back navigation. Essential actions need visible touch controls and must not depend on hover, right-click or double-click. Desktop shortcuts are listed in [usage](usage.md#desktop).

## Application design boundaries

Start from an existing application with similar tasks. Reuse its frame, menu, dialog and toolbar patterns; vary the content surface to fit the work.

- **Files and documents:** Column navigation keeps the selected path and next directory visible. Use one selection action area rather than repeating preview and footer buttons; group creation and secondary commands in menus. Editors keep save, unsaved status and explicit conflict/recovery choices visible. Inspector shows a clear target, with Open and applicable Restore actions directly available. Secondary menus retain their original object and never redirect to a later selection.
- **VM project editing:** Prioritize Codex in the project toolbar and keep Tasks directly available across sections. Files start as highlighted, read-only source; manual editing is an explicit choice for each selected file. Place the path first, followed by one compact action group containing narrow-view Back, file reload and Edit or Save/Done/Cancel. Keep navigation outside the file identity so the path is not surrounded by buttons. Allow editing controls to wrap on narrow screens; keep the full path available. Ordinary automatic-update feedback belongs in the status bar so code does not move; conflicts and failures remain beside recovery actions. Shared source editors provide line numbers and syntax highlighting while the file owner retains exact content, version checks and explicit saving. Save retains the reviewed content version and environment binding, with errors beside the draft; later typing remains unsaved. Tab changes preserve the same file’s manual editing state and undo history. Directory refresh does not replace open text. Concurrent file creation retains the latest accepted creation intent; completed requests can select their new file only while the original view is active and still safe to leave. Visible files observe external writes independently of input focus: clean snapshots update without moving focus or losing reading position, while dirty drafts keep their original save expectation and show one external-change notice. Hidden views pause checks; resuming verifies the original binding. Failed checks retain the snapshot as stale, and changed VM identities require explicit reconnection. Saving, recovery and unsettled input prevent automatic replacement. File navigation, reload, editing exit and close also wait for composition to settle. Input blocking allows only the final transaction of an already authorized composition for the exact file/environment, while preventing new focus and input; accepting a clean external version starts new local undo history. Reload/reconnect that would discard an edit requires an explicit choice; recovered drafts retain their original version/binding. Keep the VM project visible and full volume/root/runtime identities in Details. A hidden editor cannot receive focus or input. [Usage](usage.md#saved-versions-and-project-files) owns current actions.
- **Project setup and results:** Creating/cloning a project preserves its submission and environment while progress is uncertain. Successful initialization needs an explicit Open Project action. Development previews open on independent browser origins and name their VM target; Stop revokes preview access without implying process cancellation. Offline backup and restoration expose their separate copy, VM creation and verified new-project steps, preserving original identities and dirty drafts. VM project windows open in Files, with Previews and Backups as explicit auxiliary tabs. Keep all three sections mounted so switching preserves drafts, selections and original recovery requests; hidden sections are inert, disable input and pause monitoring without cancelling accepted work. Keep project identity and Tasks/Codex access available across sections. Unread auxiliary recovery, errors and activity retain an entry point while another section is visible. Each section has its own scrolling; long file errors and recovery keep the editor reachable through the file section’s scroll area.
- **VM project tasks:** Task windows retain their project identity independently of file editors and prioritize history and plain-text output while monitoring. Keep the command form explicitly available without discarding unfinished input; narrow views provide a visible return to history. Show the new command's VM target beside its input and each recorded attempt's original VM beside its result. Put optional execution controls and full technical identities in expandable sections; keep normal feedback in the status bar and errors beside recovery actions. Repeated commands remain distinguishable, polling preserves list order, and bounded output pages expose both the beginning and latest output without moving a reader who chose an earlier page. Show history selection and output navigation when the available attempts or pages require them. Cancellation identifies the displayed attempt; retry explicitly creates another attempt after a final outcome. Unknown outcomes and failed refreshes stay visible, with retained data marked stale. Hidden views pause polling and input without stopping accepted work; unconfirmed submissions preserve their original request and environment for recovery.
- **Document exchange:** Keep saved-version selection, preview, destination and the primary action together. A task opened from a Codex run retains that exact target. Put origins, associations and full technical identifiers in expandable details; keep the selected revision, delivery uncertainty and recovery actions visible. Narrow project browsers give reading the full content width and restore directory selection on return.
- **Terminal surfaces:** Use a dark monospaced emulator inside shared gray chrome. Keep execution target and a compact initial-project label visible, with full paths and runtime identifiers available in accessible details. Keep interruption, reconnecting, continuing and ending distinct. Retain shell control keys alongside desktop navigation, and make wheel/touch scrolling browse history without inserting input.
- **Codex manager:** Keep the session list compact, with a clear start action, readable names/projects and context-bound row menus with touch access. Place activity beside the session name and retain a short run reference for repeated names. Full paths, run identities, timestamps and normal process status belong in **More → Details**; non-running process states and recovery errors remain visible. Keep one primary row action and More. Keep the default host folder as a compact disclosure below the new-session toolbar, with the full path available on expansion. Recent projects belong in a menu within the New in Folder directory controls, with the default folder excluded. Choosing a recent project validates and selects its directory; one Start Here action starts the session. Show each recent project name on its own line above its full parent path, using secondary text for the parent so matching names remain distinguishable without repeating the leaf directory. Use a wide menu aligned to the control’s right edge and bounded by the viewport, including narrow screens. The main content prioritizes sessions. Keep typed directory drafts separate from confirmed listings, preserve newer typing across reads and retain drafts when the picker closes. Failed directory reads mark retained listings stale and disable their navigation. Show the current path once in its input; only a differing unconfirmed draft needs a separate label identifying the retained listing. Group directory navigation controls so they wrap together at narrow widths. Menu names and parent paths preserve distinguishing whitespace and literal host-path characters while wrapping without truncation. Arrow Down opens Recent Projects; keyboard selection stays visible in a scrolling menu. Native scrolling does not select a directory or start a session, and remains inside the menu at its limits. Fit menus to the visual viewport when its height changes. Dismiss Recent Projects when its window closes, folds, minimizes or loses activation. Successful completion is ordinary secondary text without a surrounding badge, unread marker or acknowledgment. Pending requests and undismissed failed/interrupted outcomes carry warning markers. Normal readiness belongs in the status bar; failures add explanation and repair actions. **Environment** is one independent non-modal diagnostics panel with its own scrolling. Distinguish CLI availability and terminal connectivity from model readiness. Provider activity uses textual states separate from process lifecycle. Keep **Unarchived** and **Archived** as the normal list modes; show a lightweight **Action needed** text action and count beside Sessions only while actionable items exist, including archived conversations within the selected scope. Give that action an explicit accessible name, tooltip, pressed state, visible keyboard focus and a sufficient touch target without a raised border. Its temporary view returns to the previous normal mode when emptied. If a focused alert control disappears, return focus to another actionable row or the previous normal mode; a dismissed run-window alert can return focus to terminal input. Background updates never take focus. A continuation preflight cannot open its confirmation after the user leaves that action. Late starts and continuations retain a completion notice instead of activating a run after the user changes windows, workspaces or controls. Picker dismissal returns focus to an available control; Escape respects active text composition. Show working counts only when nonzero. Pending requests open the exact run; failed/interrupted alerts offer **Dismiss alert** in the action view, row menu and run window. Keep activity uncertainty and stale refreshes visible, and preserve later alerts when an earlier dismissal finishes. Run windows retain compact activity and dismissal controls without displacing terminal input on narrow screens.
- **Persistent-session actions:** Make detaching, ending and continuing visually distinct. End confirmations identify affected work. Continuation explains the new process and creates nothing on cancellation. Reconnection identifies existing work; recovery errors stay visible. The [usage guide](usage.md#codex) owns exact action effects.
- **Applications:** Make the installed directory the main surface, using shared icons and a recessed list that echoes the application-drawer launcher. Keep package selection and review in an on-demand section, with an immediate installation path for an empty directory. Review an extension's identity, version and access before installation or replacement. Keep enabled, disabled, uninstalled and unavailable states distinct. Keep **Open** or **Enable** visible and group secondary management commands in a target-bound **More** menu. **Export saved data** must distinguish the server snapshot from a window's unsaved draft. **Show on desktop** is a separate browser preference that stays usable during installation requests or catalog errors; it neither installs nor starts an application. Offer it for launchable built-ins and extension records, including retained uninstalled records. Disabling and uninstalling retain user data; permanent data deletion has a separate confirmation. Missing applications preserve their window and launcher references. Version changes require an explicit reload that protects unsaved work; errors and recovered drafts stay visible. The surrounding window uses shared controls even when its content comes from an isolated extension.
- **Virtual Machines:** Identify the deployment machine and review storage, downloads and installation changes before confirmation. Keep blockers, progress and recovery actions visible; put successful checks and advanced diagnostics in expandable details. Preparation remains observable after reopening, and completion leads directly to VM controls. Inventory icons have readable names and textual states; actions retain their selected host and machine. Distinguish loading, offline, missing dependencies and empty or filtered inventories with useful next actions. The non-modal Inspector puts state, resources and guest access before configuration details. Preserve unfinished forms when switching views. Machine deletion and permanent volume deletion need distinct confirmations. The [usage guide](usage.md#virtual-machines) owns workflows, action labels and platform-specific behavior.

Long paths and diagnostics wrap or scroll within their content area. Session organization must keep active work visible. Terminal close/end messaging must match the distinct [host](usage.md#host-terminal), [Codex](usage.md#codex) and [guest](usage.md#virtual-machines) lifecycles.

## Narrow screens and accessibility

Fit the active window to the available area while retaining launch and workspace controls, and restore desktop geometry at wider sizes. Toolbars may wrap; menus and dialogs remain bounded; content scrolls within its own area. Short viewports use a compact shell with menu and Clip access retained; sufficiently wide landscape views move the Dock to the side. Use available height as well as width when fitting content, and keep a keyboard-reduced narrow viewport at full application width. The [desktop geometry contract](desktop.md#geometry-and-desktop-icons) owns the shared layout conditions and persistence.

Desktop icons align to the right of usable canvas, leaving launch and workspace controls accessible. [Desktop geometry](desktop.md#geometry-and-desktop-icons) owns fitting, reserved space and independent compact/wide positions. Allow two label lines, with full names in accessible labels/tooltips. Overflow scrolls inside the canvas; touch swipes over icons and empty space scroll while taps and long presses retain activation and menus.

The Virtual Machines launcher and individual VM icons use distinct original virtualization drawings. Resource icons show names and textual state, and offer target-specific actions rather than virtual-file actions. [Desktop architecture](desktop.md#geometry-and-desktop-icons) owns their identity and routing.

Follow shared responsive control sizes and hit areas. Keep primary actions and recovery options reachable without page-wide horizontal scrolling. Use semantic labels and visible focus; active, selected, disabled and error states must not rely on color alone. Respect reduced motion.

## Acceptance checks

- Review changed scenes across the browser, display-scale and touch projects in [Playwright configuration](../playwright.config.ts), using the desktop, compact and narrow scenarios in [visual tests](../tests/visual.spec.ts). Add fractional scale, browser zoom or smaller application bounds when the change affects them; do not hard-code review dimensions into layouts.
- Exercise active/inactive, folded, minimized/restored and workspace-switch states. Verify retained content, selection and scroll position. For geometry changes, cover an empty and occupied miniwindow strip, sticky windows and restoration. Include applicable empty, loading, error, disabled, selected and unsaved states.
- Complete the primary flow with pointer, keyboard and touch. Check focus order/return, owner-bound menus, cancellation, scrolling and visible alternatives to gestures. Compare actual application screenshots with Component Gallery and established applications.
- Reject unrelated rounded cards, excessive spacing, decorative soft shadows, mismatched icons, unreadable text, missing focus, hover-only actions and clipped controls.

Record viewport, scale, browser and interaction state with visual-review results. Keep screenshots/reports outside versioned source. Review behavior as well as images: a screenshot cannot prove focus return or preserved state. Commands and test isolation belong in [development](development.md#verification); update this guide only when an enduring design rule changes.
